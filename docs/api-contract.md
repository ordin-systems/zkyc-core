# Full-Stack API Contract

Request bodies accept only `application/json` or an `application/*+json` media type. Unsupported media types fail with `415 UNSUPPORTED_MEDIA_TYPE`; unknown top-level fields, malformed JSON and prototype-control fields fail with `400 INVALID_REQUEST`. Nested own `__proto__` keys inside `actionContext` remain canonicalized data and are covered by the core collision regression.

## Routes

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/health` | Reference state/version signal |
| `POST` | `/credentials` | Issue an in-memory issuer-registry credential |
| `POST` | `/credentials/:credentialId/revoke` | Revoke a registered credential |
| `POST` | `/evaluations` | Evaluate authority and optionally issue an `ALLOW` receipt |
| `POST` | `/step-up/requests` | Create step-up from retained `decisionLogId` |
| `POST` | `/step-up/requests/:requestId/resolve` | Approve or reject through an approver credential |
| `POST` | `/step-up/authorizations/consume` | Verify complete step-up bindings and consume once |
| `POST` | `/receipts/consume` | Verify complete receipt bindings, credential and nonce |
| `GET` | `/decision-log` | Return defensive-copy reason-coded decision/receipt entries |

Receipt-history summaries contain the algorithm, signed payload and a hash of the signature. The reusable signature is deliberately omitted from the unauthenticated read-only history surface.

## Authority outcomes

`ALLOW`, `DENY`, `STEP_UP`, rejection, expiry, replay and binding mismatch are authority results—not transport exceptions.

## Receipt issuance

`/evaluations` accepts `issueReceipt`. A receipt is returned only when the decision generated by that request is exactly `ALLOW / POLICY_ALLOW`. `DENY` and `STEP_UP` never receive receipts. There is no arbitrary signing route.

## Step-up provenance

`/step-up/requests` accepts:

```json
{
  "decisionLogId": "decision-log:example",
  "expiresAt": "2026-08-09T05:00:00.000Z"
}
```

It does not accept a decision object. The adapter retrieves the evaluator-produced decision from its internal map and the core requires a bound `STEP_UP / HUMAN_APPROVAL_REQUIRED` outcome.

## Receipt consumption binding

Every field is required before nonce consumption:

- `subjectId`;
- `action`;
- `actionSensitivity`;
- `resourceId`;
- `contextHash`;
- `policyId`;
- `policyVersion`;
- `credentialId`;
- `decision`;
- `reasonCode`.

Nonce and timing fields remain signed and time-validated, but are not caller-supplied expected bindings.

## Error shape

Transport/input errors use:

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "request body is invalid"
  }
}
```

Unexpected failures return a generic fail-closed response without raw internals.
